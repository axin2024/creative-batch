# 电商品牌视觉素材工作室｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 商品与品牌 | product(brand,sku,color), brand_rule(brand,rev), asset_right(asset,scope,expiry) | 每个商品色款绑定原始图、不可变包装元素、色板与授权范围，品牌方审批母版。 |
| 模板与规格 | template(brand,rev,layout), channel_spec(channel,rev,width,height) | 模板声明商品遮罩、文案域、留白、分辨率与字体资源；渠道变更规格不回写旧批次。 |
| 批量计划 | batch(brand,input_rev,budget), task(batch,variant,spec,ordinal) | 按变体、规格、候选数展开，先给总量和费用上界，运营确认后冻结输入。 |
| 模型生成 | generation(task,provider_ref,state), candidate(task,asset,model_rev) | 模板固定模型、参数与种子可用性，生成结果携费用及来源；结果未知先查单。 |
| 质量与品牌审核 | quality_check(candidate,rule,verdict), review(candidate,actor,reason) | 自动规则与人审分开，颜色、包装文字、变形、背景及标识逐项记录原因，候选可被退回。 |
| 版本与采用 | selection(campaign,variant,channel,candidate,rev) | 每个活动、色款、渠道版本最多一份有效采用，改选只影响相关输出，历史包留摘要。 |
| 交付与授权 | bundle(campaign,rev,digest), bundle_item(bundle,asset,right_rev) | 导出前逐项验尺寸、审核、授权期限和渠道。撤回授权后列出已交接包及其领取人。 |
| 生产运营 | model_usage(task,cost,source), eval_set(product_group,label) | 比较后端产出、人工采纳与返工原因，按商品隔离评测，避免相同近似图跨训练与验证。 |

## 事务、索引与对账

- **身份与约束**　品牌＋SKU＋颜色稳定，任务按冻结输入及候选序号唯一，采用按活动与规格唯一。
- **业务索引**　按授权到期日列受影响素材，按批次与单元列缺候选，按包版本反查来源。
- **数据生命周期**　品牌私有素材与公开演示样例隔离，源授权撤销后标记所有受影响交付。

批次按商品、画幅和变体冻结输入摘要，供应商任务只登记一次；发布时验证采用项与授权快照。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

导入商品图与授权表；适配器返回任务标识、候选图和费用；导出素材包、渠道清单、授权和版本摘要。

提交商品、画幅、模板版和可用授权，先输出任务数量与费用估计，确认后才能提交真实生成。

导出按商品、颜色、渠道及活动期检查唯一采用项、授权有效期和尺寸，返回包与逐项清单。

## 数据恢复与核验

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。错误候选退回，缺权素材阻断交付。每颜色每渠道各采用一张，共六项交付，清单有商品、模板、输入及采用理由。
